# Initial Risk Register

| Risk | Why it matters | Mitigation / validation |
|---|---|---|
| Empty-world network effect | Trading and guild play need counterparties | Populate with honest, functional NPCs; test human agency with small cohorts |
| AI simulation vs. human enjoyment | Active NPCs can look like engagement in dashboards | Separate human metrics, user interviews, repeat sessions and choice impact |
| Runaway progression | Early adopters become unbeatable | Diminishing returns, non-combat specializations, level-banded activities, economic relevance |
| Economic instability | Inflation, exploitation, treasuries running dry, monopolies | Conservation constraints, sinks/sources, scenario sweeps, transaction replay |
| AI cost / latency | Continual LLM inference scales badly | Rules for frequent behavior, event-driven strategic calls, quotas, caching |
| AI rule bypass | Prompt injection or hallucinations could corrupt world state | Treat model outputs as untrusted action proposals; validate every command server-side |
| Players manipulating NPCs | Social-engineering an agent can transfer assets unfairly | Bounded permissions, spending limits, audits and incident review |
| NPC deception | Users may feel tricked by artificial 'players' | Transparent NPC labels and separate human player metrics |
| Content and safety | Harassment, exploitative mechanics, age issues | Moderation design, consent settings, player reporting, safe roleplay constraints |
| Security / fraud | Duplication, race conditions, bots, multi-account exploits | Atomic transactions, auth, rate limits, logs, adversarial tests |
| Monetization / fairness | Pay-to-win can compromise competitive trust | Supporter perks and cosmetics first; no pay-only combat supremacy |
| Over-scoping | Social MMOs are operationally complex | One settlement, narrow prototype, explicit milestone exits |
